# 模型可靠性与页面加载

## 推理错误处理

连接测试和策略推理使用同一个 HTTP 传输层。对 408、429、500、502、503、504 及部分暂时性网络错误，最多尝试 3 次，各次尝试使用剩余超时预算。遵守 `Retry-After`；如果等待时间超过剩余预算，则失败而不是提前重试。

- 每次重试保留原模型、消息、思考强度及 JSON 参数，不自动换模型或降级 `high`。
- 400、401、403、404 等参数或认证错误不重试；证书错误不绕过。
- 空正文、非法 JSON 或错误响应不会被标记为连接成功。
- 错误日志包含状态码和尝试次数，不记录密钥、请求内容或原始错误正文。
- 重试仅适用于模型推理，**不应用于下单、撤单、平仓等交易写请求**。
- 失败或未取得执行锁时仍禁止使用旧指令开仓；汇总日志区分锁占用、接口错误和无有效输出。

这能处理暂时性服务波动，但不保证持续不可用的上游模型服务一定恢复。不能用简单的 PONG 请求证明完整策略请求始终成功。

## 监控数据加载

- `/api/all`、`/api/overview` 有可用快照时立即返回，不等待交易所网络请求。
- 过期快照在返回时标记 `STALE`，刷新在后台进行；冷启动返回明确的初始化状态，不伪造余额。
- 缓存生产者共用 single-flight 锁，避免后台线程与多个页面请求同时重复采集。
- 缓存必须匹配当前账户/交易环境，切换账户后不能继续展示旧账户快照。
- 前端合并正在进行的相同 GET 请求，不缓存已完成的管理配置；会话不同或发生写操作后的读取不会共用旧请求。
- 监控轮询不重叠，隐藏标签页暂停轮询，重新可见时刷新；不影响服务器采集任务。

## 管理页面

- 账户设置与标的池先加载，较慢的 OKX CLI/网络诊断独立显示进度，不阻塞整页。
- 诊断结果以请求代次区分，旧请求不能覆盖新配置的结果；后台诊断缓存随凭据变化失效。
- 运行总览不再重复请求已经包含在 runtime 响应中的配置摘要。
- 导航意图（鼠标悬停、键盘聚焦）预加载页面代码，不提前读取账户数据。
- 关于页在 Docker 中读取构建元数据，不依赖镜像内 `.git`；查看页面不隐式执行远端 Git fetch。
- 登录恢复避免重复校验，失效会话不额外发送无效注销请求。

实际加载时间仍受网络往返和浏览器影响。应分别记录接口响应时间、诊断时间和表单可交互时间，不把诊断缓存命中或一次测量当作所有页面的通用加速比例。
